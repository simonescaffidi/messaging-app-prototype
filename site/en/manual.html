User manual

1. Sign-up and first login

On the start screen, tap "Sign up" and enter your email and a username. No phone number is required.

After signing up you'll see three pieces of information only once — save them right away somewhere safe (a password manager, for instance):

  • Access code: this is your "password" — every time you open the app you enter it, and your profile opens automatically.
  • Public ID: this is what you share with people you want to add as contacts. It never reveals your email.
  • Secret combination: used to reveal hidden chats (see the dedicated section).

If you lose your access code, you lose access to that profile: there's no real email-based recovery yet (see "Stated security limits").

2. Multiple profiles on the same device

You can create several profiles (for example a personal one and a cover one), all reachable from the same device. Each profile has its own access code: when you open the app and enter a code, the matching profile opens automatically — there's no selection screen that would reveal how many profiles exist.

3. Adding contacts and chatting

Tap "+ Add contact" and enter the person's public ID. A real-time chat opens, end-to-end encrypted (see section 7).

4. Hidden chats and the secret combination

From a chat, open the menu and choose "Hide/show this chat". A hidden chat no longer appears in the main list.

To bring it back, type your secret combination (the one shown only once at sign-up) into the search bar: all hidden chats reappear until you lock the app again.

5. Cover profile

At sign-up you can check "Create as a cover profile": a profile meant to be shown if asked to, with no hint that other profiles exist on the same device.

6. Timed (self-destructing) messages

Before sending a message, you can pick a self-destruct time from the dropdown: 30 seconds, 5 minutes, or 1 hour. Once that time passes, the message is removed.

7. End-to-end encryption: how it actually works

This isn't a marketing slogan: every message is encrypted in your browser, before it's sent to the server, using this scheme:

  1. On first login, your device generates an ECDH key pair on curve P-256 (one public, one private). The public key is uploaded to the server; the private key stays only in your browser.
  2. When you message a contact, your browser combines your private key with their public key (an ECDH exchange) and derives, via HKDF-SHA256, a 256-bit AES-GCM symmetric key specific to that pair of people.
  3. Each message is encrypted with that key and a different random number (an IV) every time, then sent to the server already encrypted.
  4. The server only stores and transmits ciphertext: it cannot read the content of your messages.

This is the same type of math (ECDH + AES-GCM) used by many modern secure protocols, applied here through the browser's native Web Crypto API, with no external libraries.

8. Biometric unlock (Face ID / Touch ID / fingerprint)

In the profile settings (⚙️ icon) you'll find "Enable Face ID / fingerprint unlock". Turning it on makes your device create a passkey via WebAuthn/FIDO2 and register it with the server (only the public key, never the biometric data itself).

From then on, the login screen shows an "Unlock with biometrics" button: use it instead of the code, and your operating system (not the app) verifies Face ID, Touch ID, Android fingerprint, or Windows Hello. Biometric data never leaves your device.

You can turn it off at any time from the same settings.

9. Changing language

In the top corner of every app screen you'll find a language selector. This website is available in the same 11 languages too: Italian, English, Spanish, French, German, Portuguese, Arabic, Chinese, Hindi, Russian and Japanese. The language you pick in the app is remembered on the device.

10. Native mobile apps (iOS/Android)

A native app scaffold (built on Expo/React Native) is ready, adding a system-level biometric lock on launch. Actually publishing to the App Store and Google Play requires the developer account credentials (Apple Developer Program and Google Play Console); once those are connected, the app can be built and published. Until then, the webapp remains usable from any mobile browser and can already be "installed" to the home screen like an app.

11. Stated security limits

In the interest of honesty, here's what this prototype does not do yet, even though the encryption itself is real:

  • No ratchet / forward secrecy: a chat's key stays the same until both people regenerate their keys (unlike protocols such as Signal, which rotate keys with every message).
  • No out-of-band verification of public keys: there's no "safety number" to compare out loud with a contact. In theory, a malicious server could swap in its own public key (a man-in-the-middle attack). Fine on a trusted server for a prototype; this verification should be added before any high-risk use.
  • Private key lives in the browser: it's stored in the browser's local storage, not in a hardware secure enclave. Anyone with physical or software access to your unlocked device could read it.
  • No real email sending: sign-up works, but there's no email service connected yet for a "magic link" account-recovery flow.

12. Troubleshooting

"Can't encrypt: the contact doesn't have a public key yet"

This happens if your contact hasn't logged in since the latest app update (the key is generated and uploaded automatically at login). Ask them to log in once — after that you'll be able to message them normally.

"I lost my access code"

There's currently no automatic recovery: you'll need to register a new profile. Always keep your code in a password manager.

Biometric unlock doesn't show up

It requires a device with Face ID, Touch ID, a fingerprint sensor, or Windows Hello set up, an up-to-date browser, and an HTTPS connection (the production webapp already uses one). It also needs to have been enabled at least once from settings.
